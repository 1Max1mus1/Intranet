# Intranet 技术验证计划

## 原则

第一阶段不开发托盘、主界面、自启动或安装包，不直接同步真实工作目录。已有代码只能作为一次性材料，复用前必须证明符合已确认规则。每次只推进一个主要风险，记录预设门槛和原始结果，不在实验后悄悄改标准。

## V0：环境与基线

- 登记两台电脑的 Windows 版本、CPU、内存、硬盘类型、网卡和路由器连接方式。
- 创建专用测试目录，包含文档、图片、代码、中文与长文件名、空文件、嵌套目录、大文件及大量小文件。
- 真实文件只使用副本。
- 在同一网络测量 Windows 文件共享的大文件吞吐，保留原始命令和结果。

**通过条件**：测试数据可重复生成，基线可重复测量，真实目录未被接入。

## V1：同步正确性

用两台真实电脑验证新增、修改、删除、重命名、移动、排除项和离线补同步；覆盖双方分别操作以及同一批嵌套文件。

**通过条件**：两端内容和文件身份符合 PRD；重命名且内容未变时不重传；排除项不传播删除；删除记录能阻止离线旧文件复活。

**修订或停止条件**：无法设计出不依赖临时人工规则的版本模型，或出现无法解释的旧版本覆盖，暂停扩大实现，先修订模型。

## V2：冲突与历史

覆盖双方离线修改同一文件、删除与修改竞争、连续冲突、恢复历史、30 天和容量清理规则。

**通过条件**：双方内容均可恢复，原路径选择符合规则，冲突副本清晰，历史清理不删除同步元数据，不发生静默丢内容。

## V3：中断与续传

在下载、校验、替换和状态记录的不同时间点模拟断网、杀进程和重启；对大文件反复中断并恢复。

**通过条件**：原完整文件始终可读取，半成品不会成为成功版本，恢复后续传或重传得到一致摘要，状态不会假报完成。任一数据损坏均为阻塞失败。

## V4：发现与性能

- 测量设备发现和断网恢复时间。
- 测量不超过 10 MB 文件的端到端同步时间。
- 测量大文件吞吐并与 V0 基线比较。
- 在广播不可用时验证手动 IP 备用路径。

**通过条件**：发现/恢复 ≤ 10 秒，小文件 ≤ 5 秒，大文件吞吐 ≥ Windows 文件共享的 70%。未达标时先定位瓶颈和优化，不进入第二阶段；若硬件或网络限制导致目标不现实，必须带证据交回用户决定是否调整承诺。

## V5：安全边界

验证错误配对码、未配对设备、伪造设备、未知网络和传输加密；检查配置与日志不泄露密钥或敏感文件内容。

**通过条件**：未授权设备不能读取或修改同步空间，未知网络默认暂停，日志和持久化不包含明文秘密。

## 当前可重复验证命令

```powershell
python -m pip install -r validation/requirements.txt
python -m validation.corpus --root .validation-data/corpus
python -m validation.run_checks
```

结果写入 `docs/evidence/local-results.json`。这些命令只操作 `.validation-data` 和临时隔离目录；其中 V1/V2 为单进程双目录，V3/V5 为回环 TCP，不能替代下述双机门槛。

## 第一阶段完成定义

- 每项实验都有原始证据、环境、结果和继续/修订/停止结论。
- 数据安全门槛全部通过；其他未达门槛已获用户明确决策。
- 用户审查验证结果并明确批准第二阶段后，才开发产品外壳。
