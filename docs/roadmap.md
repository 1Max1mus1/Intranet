# Intranet 路线图

## 阶段 0：立项（已完成）

- 明确两台设备、一组同步空间和云盘式局域网体验。
- 确认同步、冲突、历史、安全、通知和验收规则。
- 建立项目 Wiki，已有代码只保留为验证材料。

## 阶段 1：同步引擎技术验证（下一阶段）

按 [技术验证计划](validation.md) 依次完成 V0–V5。只使用测试目录和副本，优先关闭数据损坏、旧版本复活和中断恢复风险，不做产品外壳。

**阶段出口**：验证报告经用户审查，明确批准进入第二阶段。

## 阶段 2：完整产品落地

以可演示增量交付，不把全部功能留到最后：

1. 首次设置、目录选择、配对和受信任网络。
2. 后台同步服务、托盘状态、暂停与恢复。
3. 冲突提示、历史查看与恢复、排除列表。
4. Windows 登录自启动、主界面和诊断信息。
5. Windows 安装包、卸载和配置保留/清理路径。

界面不追求精美，但必须状态清楚、操作直接、适合个人日常使用。

## 阶段 2 验收：真实试用与发布候选

- 使用真实工作目录连续试用至少 7 天。
- 记录同步失败、冲突、恢复、资源占用和手动兜底行为。
- 关闭数据丢失、损坏、无法恢复等阻塞问题。
- 达到 PRD 验收标准或由用户明确接受限制后，形成个人使用发布候选。

## 阶段 3：Tailscale 远程文件传输助手（已确认方向）

- 通过 Tailscale 提供类似“文件传输助手”的按需远程发送。
- 用户主动选择文件并发送，不要求开启或持续运行文件夹自动同步。
- 使用已保存的 Tailscale 设备地址，不依赖 UDP 广播。
- 复用配对、应用层 TLS、分块校验和断点续传能力，明确 direct/DERP 路径和性能限制。
- 按需传输不承诺目录镜像、删除传播或持续冲突协调；具体流程和验收在第三阶段立项时确认。

## 暂不安排

多设备、多同步空间、云端文件存储、在线占位符和通用用户系统均不进入当前路线。跨城市按需传输已纳入第三阶段，但不提前到第一、二阶段实现。
